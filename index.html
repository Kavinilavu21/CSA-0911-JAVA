Problem Statement

Educational campuses suffer from recurring vehicular congestion, unauthorized parking in faculty zones, time wastage searching for unoccupied slots, and paper ticketing errors. Traditional gatekeepers lack real-time visibility into multi-floor capacity and fail to apply transparent role-based tariff discounts.

Project Objectives

  • Automate slot allocation across 5 distinct parking floors.
  • Eliminate duplicate vehicle registration via validation checks.
  • Implement transparent multi-role tariff calculation engine.
  • Generate verifiable digital parking tickets with barcode & timestamps.
  • Offer rich auditing, floor occupancy reports, and CSV data export.

System Scope

Designed specifically for multi-tier university parking complexes. Accommodates 96 slots across 5 specialized floors catering to 5 vehicle categories: Two-Wheelers, Four-Wheelers, Electric Vehicles with charging bays, E-Bikes, and Campus Delivery Vans.

Technologies Used

  • HTML5: Semantic markup, forms, modals, SVGs.
  • CSS3: Modern flexbox, CSS grid, variables, print queries.
  • JavaScript (ES6+): Stateful routing, data engine, timers.
  • LocalStorage API: Client-side persistence for assignment demo.

Mapping to Java OOP Concepts (CO1 Alignment)

How this web dashboard maps directly to Java Class Hierarchy & Object-Oriented Principles
Encapsulation & Entities
class Vehicle
Private attributes (regNo, owner, role, category) with getters/setters, input validation, and unique constraint checking.
Inheritance Hierarchy
Car, TwoWheeler, EVehicle extends Vehicle
Subclasses inherit common vehicle properties while defining specific hourly tariffs and fast charging capabilities.
Polymorphism (Tariff Strategy)
interface TariffCalculator
Different fee calculation algorithms execute dynamically based on the runtime vehicle instance and role discounts.
Aggregation & Composition
class ParkingFloor • ParkingSlot
A Campus ParkingLot has a 1-to-many relationship with 5 ParkingFloors, which in turn contain 16-24 ParkingSlots.
